# LangGraph整体设计与迁移边界

## 唯一编排层

四个图由orchestration统一定义，业务层不再构造StateGraph：

生命周期图 → 有界事件图 → 工具图 → 决策图（工具提案阶段调用）。
科学结果回收分析先于建议；人工审批与预算校验先于工具执行；每步结果入账后才允许下一步。
图状态集中于state.py；节点适配与决策节点单独组织；模型客户端等调用期依赖放入Runtime上下文。
科学实现、数据存储、预算校验与UI维持功能分层，不用图替代数学函数或文件格式。

## 原生恢复实施顺序

当前审批恢复已落地，见NATIVE_APPROVAL_RECOVERY.md；以下顺序针对完整科学工作流的进一步恢复，不表示审批仍未实现。

先设计RunIdentity（工作区、epoch、配置版本、action key），将业务可恢复数据与运行依赖彻底分开。
再给每类副作用建立准备、执行、入账和不确定状态协议：文件已写或远端提交不确定时只能校验，不可自动再提交。
然后对审批节点接入持久interrupt，核对方案hash和版本；旧待审记录须明确导入或拒绝，不可默认批准。
最后启用本地持久checkpointer，并通过重启、重复回复、写入中断、并发工作区等故障测试。
这些改变不应以空langgraph.json或内存checkpointer冒充完成。当前本地服务不使用Agent Server部署配置。

## 不扩大授权

修改项目不授权分析现有数据、生成训练/科学任务、修改确认配置或提交超算。真实API和服务端验收另行执行。
