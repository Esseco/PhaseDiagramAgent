# 对话与科学工作流分离

常规自然语言先经现有 LLM 意图接口理解。read_only 直接返回简短回答；other 进入无工具的对话判定，而不是默认重跑科学决策。只有明确的方案修改或操作请求，且满足 direct_request/置信度校验，才作为原话反馈进入原工作流。LLM 无权生成审批授权。

当前启用范围：read_only 简短回答及未知消息不推进任务。包含本地路径、近期聊天的上下文问答默认关闭，生产入口未启用 enable_context；需要用户明确批准对话载荷向现有 DeepSeek API 外发后再接入。下述上下文构建及反馈判定目前仅有合成测试，不代表已在服务中启用。Deep Agents 专用问答通道尚未接入。

查看已有方案：常见“看看方案/方案呢”直接走本地只读查询；其他同义表达可由意图接口映射为 view_plan。响应从保存的待审批记录生成，仅列动作、目的、成本或必要冲突提示，不重新分析、批准或执行。无方案时说明无方案；多个方案时列出目标，不猜测。此路径不需要新增上下文外发授权。

对话上下文由 run/conversation_context.py 的白名单构建：当前模型、任务状态计数、登记训练目录、相图路径、待审批动作类型和最近六条文字消息。不会读取原始结构、轨迹或发送完整配置。最近消息每条最多1200字符，产物条数有上限；这不是替代现有科学决策记忆的新记忆系统。

默认回答1至3句：问路径就给路径，问原因就解释原因，不重复全部误差、总结、审批模板。详细内容仅在用户要求时展开。模型缺少事实应说明未知；登记路径不等于文件存在。明确目录查询仍可由现有只读路径工具直接回答。

LLM失败或返回格式无效时停留对话，不能借故推进任务。离线、未配置 LLM 的兼容调用仍保留原入口行为。已有明确的状态、继续、导出、审批和重生成指令继续使用原有处理链；当前方案不重构审批、文件替换和恢复机制。

修改代码后需重启本地 Agent 服务，运行中的旧进程不会自动加载新对话逻辑。测试使用模拟 LLM 和临时文件，不调用线上服务、不生成真实任务。
