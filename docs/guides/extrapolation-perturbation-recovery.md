# 新外推恢复：唯一微扰路线

新决策只接受 prepare_parent_first_recovery。完整刷新证据失败比例 <10% 继续，>=10% 进入微扰恢复；不完整保持未知。模型更新次数不影响路线。历史冻结输入、审批与旧执行入口按旧契约，不自动迁移。

顺序：小扩胞母帧 → MH-1成功弛豫 → 微扰 → 几何合理性 → 相对弛豫母帧的 M3GNet 特征向量欧氏差 <=1 → DIRECT → 原恢复DFT与训练。无微扰后MLIP再弛豫。参数继续来自 parent_first_handoff / parent_first_sampling / Process_MLIP.nepkit_sampling；不更改标签、次数、训练激活审批边界。外推结构与风险证据仍可供常规DFT审查。

# 外推失败后的两条恢复路线

## 当前规则：epoch 刷新

仅在新模型 epoch 的结构刷新范围中触发外推补充。Relax–MC 保留弛豫外推证据供普通 DFT 选点，不单独触发恢复。比例只统计该刷新中实际弛豫的去重结构；覆盖不全保持未知。

新建 Relax–MC 任务的初始 Relax 与 MC 内部弛豫采用初末态 M3GNet 特征差严格大于 3 的异常阈值；模型刷新仍严格大于 1。完成的 Relax–MC 不因该监测进入外推恢复采样，后续由项目根据搜索与 DFT 证据判断继续探索或补充 DFT。该规则不改写历史冻结任务、结果或审批；旧批次如需按新规则继续，必须另行核验来源、完整监测和续跑入口。

失败比例低于 10% 不补充。达到 10% 时，初始模型（epoch 0）和第一次模型更新使用微扰采样；第二次模型更新起，低于 20% 使用外推结构，达到 20% 使用微扰。每个 epoch 最多补充 5 次，每个外推轮次累计达到 50 个合格、去重的 DFT 标签且本轮全部 DFT 任务回收后微调。新模型从失败前的同一有效凸包重新弛豫、刷新并检查；仍达到 10% 则进入下一外推轮次，低于 10% 才结束恢复。外推轮次不增加科学 epoch；模型版本顺序仍单独记录。新规则只绑定新批准的恢复方案，旧冻结方案继续按原规则恢复。

外推策略模块只判断比例、路线、次数和已验证标签数量；初始模型与第一次更新的强制微扰规则依据实际模型更新顺序，而不是补充次数或科学 epoch 的显示名称。DFT 任务仍由现有 DFT 流程负责。与恢复帧完全绑定的 DFT 失败按原因汇总，不自动重试，也不因 20% 门槛反复等待诊断；不能完成身份绑定的批次仍按原 DFT 规则处理。未结束和状态未知的任务不视为失败或成功。旧模型和无上一有效相图时不得伪造母帧或基线。

新外推采样路径包含 `round_轮次_attempt_序号_路线_摘要`，新微扰输入目录包含 `extrapolation-round-轮次-perturbation-attempt-序号`；历史文件路径不迁移。每次采样保留回执、结构哈希和原有审批记录。

以下章节记录原有实现和旧方案的细节；与本节规则不一致时，新方案以本节为准。

可靠性 Agent 对完整、绑定轮次的证据判断大量外推失败；Strategic 在以下两条路线中给出方案和原因，批准包含后续同范围的 DIRECT、DFT 和微调准备。

1. **外推结构微调**：从本轮可核验末态中选取特征差不大于 1 的帧；大于 1 或同帧特征差缺失的帧不参与采样。
2. **微扰结构微调**：Agent 选择上一有效相图中外推正常、小 det(H) 的母帧，按相和 Na 含量覆盖；将母帧、参数及合格已成功 DFT 参考通过必要文件压缩包交给 HPC。HPC 先用原始 MACE-MH-1 弛豫母帧，再调用 Process_MLIP 生成和检查微扰帧、以成功 DFT 为参考进行 DIRECT 采样，仅回收选中帧及必要证据供 DFT 和微调。微扰帧不另做逐帧弛豫。**该新顺序尚待完成远端执行和 Agent 接力；旧本地先微扰入口已停用。**

两路线的 DIRECT 采样均作为各自的独立采样；已核验且范围完整的选中帧进入 DFT 时，不再要求追加普通 DFT 独立抽查、旧凸包 GS、D/H 代表或其他额外数据。历史抽查记录保留。输入和输出帧的身份、完整性及用户确认的数量仍须核验；“独立采样”本身不等于已获得独立模型验证结果。

两路线共用 M3GNet DIRECT，合格已完成 DFT 结构作为覆盖参考。参考所在簇不再选择代表；这不是对所有相似结构的数学去重保证。两路线后续复用现有 DFT、累计训练数据、微调、模型验证和 epoch 刷新流程。恢复选帧不强加旧凸包 GS 或无关 D/H 组；普通 DFT 的 GS 和覆盖规则保持原样。

## 数据与恢复边界

- 母帧、H、组成、任务、活动模型、原始 MH-1 摘要及外推轮次摘要绑定；微扰和弛豫不改变元素顺序或 TM 排列。MH-1 上传归属于失败轮次，任务实际模型仍是 MH-1；计算端逐任务核验模型文件摘要，可能增加文件读取时间。
- 输入使用现有最小压缩包和任务回收协议。已经登记的输入重复进入时只在清单、任务和压缩包仍有效时复用；输入有变化时阻断并保留现场，不覆盖或重算。部分失败时等待所有旧 DFT 任务结束，保留旧周期及成功 DFT 数据，再允许提议切换至微扰路线。
- 微扰帧为训练池，不加入正式相图或下一轮相图搜索刷新。失败 epoch 保留且不作为 latest；新模型通过验证并激活后，从上一有效相图按项目既有最新结构规则刷新。
- 原批准只可复用于同轮经验证的微扰 DIRECT、精确选中的 DFT 帧和标签齐全后的训练准备；异常范围、缺失证据或改变的帧不能自动通过。远端计算、结果回收和模型激活仍遵循项目运行环境及现有交付流程。

## 验证与限制

测试以 `py1`、临时合成项目、模拟模型和计算结果运行；两路线分别通过 DIRECT、失败相图隔离、DFT 标签核验和实际微调输入包生成，微扰路线还验证 MH-1 输入包和 DFT 选点图门槛。模拟结果不是 MACE、VASP 或 HPC 实算，也不能证明服务器环境兼容。历史 `test_complete_training_epoch_flow.py` 的旧夹具只有一个 Na 端点，不能满足当前需要完整端点和历史记录的凸包规则；该旧全流程测试尚需以完整相图夹具更新。

`prepare_nepkit_initial_dataset` 是独立初始化入口，仍仅有参数契约；这里接入的是外推失败后的微扰结构微调路线，不代表独立初始化入口已完成。

## DFT 失败暂停与分析

同一模型、上传操作、父轮次和重试轮次的 DFT 任务按批统计；达到或超过 20% 即暂停后续科学动作并交给 Agent 分析。完整批次用已回收的成功、失败和超时计算作为分母，取消项不计入；还有未结束项目时，把它们视为可能成功，只有即使全部成功仍达到 20% 才提前触发。未回收、提交状态未知和主动取消不算失败，暂停不会取消正在运行的任务，也不自动重算。

暂停证据绑定批次、失败任务及错误记录；Simulation Agent 分析必须引用具体批次结果。若诊断不可用或证据发生变化，暂停保持；项目状态和决策上下文会显示当前门槛与待分析状态。Codex 原生 Agent 可通过 `phase_register_dft_failure_analysis` 登记绑定 `failure_evidence_digest` 的结构化诊断，该入口只登记分析，不创建、提交或重试任务；它校验诊断格式和证据引用，不保证诊断结论一定正确。分析完成后，Strategic 根据证据提出后续方案，沿用现有审批和必要压缩包流程。


## 历史末态证据和不再等待

经项目 Agent 完整核验并绑定刷新任务的历史初末态筛查，可在逐步监测缺失时计算保守失败下界：按不同结构去重统计已确认失败，并以整轮不同结构为分母；下界达到 10% 时允许进入 DIRECT 恢复路线。该结果不标记逐步监测完整，也不能推断逐步受力或灾难性遗忘；文件校验或绑定失效时保持未知。

用户明确不再等待已回收批次的指定 DFT 任务时，可通过 `phase_register_dft_wait_waiver` 登记完整且精确的待确认任务列表和用户原话。该入口复用已有恢复决定，结束本地任务跟踪并保留原状态和用户决定，不向 HPC 发送取消，不重试；任务列表与当前批次不一致时拒绝。原批次满足既有结束条件后可以提出切换，已完成结果仍被保留。


当微扰结构微调的审核动作明确设置 `direct_target` 时，该数量绑定后续 DIRECT 自动承接：目标变化、合格去重候选不足或扣除成功 DFT 参考后实际选中数不足，均停止并返回分析，不自动缩小数量。旧动作没有该字段时沿用旧行为。


## 旧顺序遗留的未登记帧

当微扰帧清单已经写出，但任务与上传批次尚未持久化时，这些文件是实际产生的部分产出，不得将该动作标记为无副作用，也不得直接把文件当作已经登记的任务。执行恢复入口支持 `verified_abandoned_staging`：核验原批准动作、清单、母帧和帧哈希，并检查不存在相关任务及上传批次；人工敏感确认后保留原文件和回执、禁止旧动作重放。这些在母帧弛豫之前生成的帧不得用于新流程。失败现场和原数据必须保留，不得直接改写项目台账。

旧顺序入口已禁止继续执行，既有文件保留作为失败现场。新的 HPC 先弛豫后微扰链路已在源码中接入并进行合成测试，尚须远端计算节点验证。


## HPC 母帧先弛豫流程的接入进度

`phase_agent.science.mlip.parent_first_sampling.run_parent_first_sampling` 是处理核心：先检查输入及 MH-1 摘要，逐个弛豫母帧并核验收敛、外推和 TM 位点，再复用 Process_MLIP 生成并筛查微扰，使用成功 DFT 参考进行 DIRECT；结果只导出选中帧及清单。合成测试使用假弛豫及假特征，不等于实际模型或 HPC 验证。

源码已增加项目 Agent 的 `prepare_parent_first_recovery` 动作、母帧压缩包和 HPC 接力；旧失败动作的证据核销须经项目 Agent 敏感审核。BJ-HPC 的 Process_code 当前未包含本地 `Process_MLIP/nepkit_sampling.py`；需先在本地审查并提交相关代码，再按既有 Git 同步规则同步远端，随后在计算节点检查依赖与完整调用链。


## 母结构输入、HPC 采样与回收契约（开发中）

`parent_first_handoff.prepare_parent_first_bundle` 只打包经核验的母结构、成功 DFT 参考帧和参数，不在本地弛豫、微扰或采样。`parent_first_sampling` 的 HPC 命令行先完成全部母结构的原始 MH-1 弛豫，再调用 Process_MLIP 微扰与 DIRECT；完成的母结构弛豫采用输入和模型哈希绑定的检查点，失败时保留，不自动重算。`parent_first_result.validate_parent_first_result` 只读核对返回帧数量、哈希、母帧与模型绑定。合成往返测试使用假弛豫/特征；另有使用合成特征调用真实 DIRECT 实现的测试。

源码使用现有 Slurm 分发器接力静态 DFT，通过回执与哈希绑定选点和任务，并将结果交给现有回收和失败分析。返回帧核验只检查任务报告、哈希、组成及 TM 位点匹配，不证明中间微扰生成步骤；如需独立复现，应保留远端弛豫母帧及相关证据。远端依赖同步和计算节点验证尚未完成，不应声称真实流程已通过验证。


### 本次实现进度与剩余工作

项目 Agent 的 Strategic/Reliability 提示已明确：只提供母帧和成功 DFT 参考，HPC 完成母帧弛豫、微扰、DIRECT 和已批准的 DFT。旧本地先微扰和微扰路线本地 DIRECT 调度均被阻断。

已实现并合成测试：母帧与 DFT 参考最小输入压缩包、HPC 全部母帧先弛豫再微扰的处理核心、母帧检查点复用、100 帧目标不足时停止、返回帧哈希及 TM/组成核验、输入与结果压缩包模拟往返。还有一项用合成特征调用 Process_MLIP 实际 DIRECT 的测试；不代表实际 M3GNet 或 HPC 实算。

默认 M3GNet 特征编码器会在开始母帧弛豫之前核验检查点目录及其摘要；缺失或不匹配立即停止，避免先完成整批弛豫后才发现 DIRECT 权重不可用。正式运行仍需在计算节点验证依赖及模型加载。

`parent_first_dft.prepare_parent_first_dft` 可在核验 DIRECT 输出后，为每个选中帧生成确定身份的 atomate2 static 输入并绑定结构及采样摘要；它不登记项目作业、不提交，也不自行证明配置来自批准动作。合成测试覆盖输入篡改和重复准备，另用真实 Py-Code 静态输入生成器验证了生成设置，但没有运行 VASP。将其接入正式作业前，调用方必须验证配置绑定到受审动作，并完成 Agent 任务登记、调度、结果回收和失败门槛接力。

输入清单可冻结 DFT 配置；DFT 生成器拒绝与清单不一致的配置。`parent_first_dft_registration.register_parent_first_dft_tasks` 校验受审动作、候选帧与远端任务身份；已接入现有回收入口，以状态与结构台账的事务提交登记后，再交给原 DFT 回收器。单独的组件测试不代表真实作业已经登记或整条链路已通过 HPC 验证。

旧暂存帧核销须核验项目证据并经敏感审核。源码的合成测试覆盖 Agent 登记、输入包、HPC 先弛豫、DIRECT 及 DFT 分发、最小证据包、返回校验和 20% 失败门槛。若相图 latest 不是已核验基线，回收会阻断并报告，不能静默改写。未完成远端依赖同步、实际计算节点验证和真实项目作业提交；先前错误顺序生成的帧不用于本流程。
