# 检查与恢复一个项目

日常使用同一个启动器：`python -m phase_agent.runtime.local_project_launcher`。新项目在启动器创建独立目录，填写体系、结构边界、母结构和两端环境；已有项目选择原 `agent_runtime.json`。确认配置后使用“继续”，程序沿同一条 LangGraph 流程检查回传、分析证据、提出下一份方案，具体动作仍须审批。

新生成的数据项目还带有 `run_project.py`：在项目目录执行 `python run_project.py` 打开并选中本项目，再手动启动服务；`python run_project.py --check` 仅诊断。此入口绑定创建时的 py1 和共享源码，不复制应用、不启动科学任务。新项目的配置和入口先在临时目录生成并用真实读取器回读，发布中断会清理本次新建文件；已有结构和自定义文件保留。两种运行模式均每轮一个科学动作。

## 生成后的输入验收

普通提交包与 RelaxMC 配对交付，在生成最终压缩包及外层入口后执行同一输入验收。只有通过后才返回准备完成。已登记包再次交付时也检查；多个批次共用一个包，每次交付只检查一次。

- 流式核对 ZIP 清单、安全路径和每个文件的 SHA256，不解压到项目、不执行生成代码。
- 编译检查 Python，解析 JSON，核对 POSCAR 布局和当前提交计划引用的脚本/工作入口；运行库中的未实例化模板不作为已提交作业解释。
- 检查外层 Python 入口、Shell LF 格式、实际提交脚本和包内文件的对应关系。完整 Bash 语法由计算节点的 `bash -n` 检查。
- 远端入口在子作业提交前检查模型引用、Python 版本、必需模块是否可发现及 Bash 语法。依赖检查不导入 Torch/MACE、不加载权重；它不证明 CUDA、动态库 ABI、许可证或科学计算正确。

在源码目录可独立运行零模型检查：

```powershell
python -m phase_agent.tools.remote.input_validation --folder '交付目录' --kind dispatch
python -m phase_agent.tools.remote.input_validation --folder 'RelaxMC_input目录' --kind relax_mc
```

通过返回 0，未通过返回 2，JSON 中给出文件、代码、可用的行列和恢复方式。`remote_environment=not_checked` 表示本地验收未核实超算环境，不能解释为远端已就绪。检查不更新审批或任务状态。

检查成本不使用 token：内容指纹绑定整个压缩包、两个外层入口和校验器版本；进程内最多缓存 16 个包和 2048 条文本校验事实，缓存不保留源码或解析树。二次检查仍流式读取压缩字节确认内容，不按修改时间盲信缓存。单个 Python/Shell 限 2 MiB，其他待解析文本限 16 MiB；超限显式阻止交付并定位，不能跳过后标成通过。普通答疑与显示状态只读小型验收事实，不扫描输入包；成功事实不超过四个字段。

Windows 文件共享冲突只自动重试一次只读检查，等待 50 毫秒。语法或配置错误不盲目重试；可确定的入口由现有准备流程从模板产生。远端缺依赖或脚本预检失败时修复原环境再运行同一入口；`submitted` 回执保留，已经提交的子作业跳过。提交被中断、效果不明或输入变更时仍先对账，不因预检失败自动重放科学动作。

历史上传包保留其记录的代码与身份，不因更新本地应用自动改写已上传包。已有计算继续按原回传和恢复流程处理；若需要换用新的科学执行代码，应形成新的、经过审阅的交付，不能在旧任务目录替换文件冒充同一个输入。

## 服务未启动也能诊断

在生产源码目录、py1 环境执行：

```powershell
python -m phase_agent.runtime.project_diagnostics --runtime 'E:\0-PhaseDiagram\你的项目\agent_runtime.json'
```

输出为 JSON，只读且不调用模型、不提交任务、不启动服务。`sections` 分别报告配置、路径、状态、台账、版本绑定、母结构、执行回执和近期故障；一个文件损坏不会中止其他部分。`issues` 提供文件、错误码、JSON 行列及下一步。业务校验问题可能位于 `sections` 而不在 `issues`。

| status | 含义及下一步 |
| --- | --- |
| configuration_required | 项目尚在草稿阶段；补齐配置并在启动器确认。尚无科学状态是正常情况。 |
| needs_attention | 按文件/字段或执行恢复条目修复，再运行同一诊断命令。 |
| ready | 本地检查通过，可以打开原项目继续；不代表远端任务完成、物理结构正确或科学收敛。 |

原来的 `--state '...\workflow_state\state.json'` 仍可单独检查状态。诊断不会替用户迁移文件、修正科学参数或解除审批。

## 按故障范围恢复

项目入口清单是可恢复的导航索引，不是科学账本。清单支持 UTF-8 BOM；格式损坏时先按内容哈希保存原始文件，再保留有效条目并恢复索引。原始字节备份失败则不覆盖清单。需要恢复列表时，用“选择文件夹”重新添加原项目，无须改代码或复制项目。其他项目配置损坏会单独提示其文件，不能拖住一个独立的新项目；同目录重复项目、共用 state/台账的限制保持有效。并发注册使用文件锁和原子写入，不丢其他项目。

新项目生成完成后若恰逢入口清单被占用，保留已经通过回读的项目文件。解除占用后直接运行该项目的 `run_project.py` 或再次选择原文件夹即可完成注册，不要重新生成或手工删除配置。`--check` 始终只读，不修复全局入口清单。

准备 Relax、MC、DFT 或模型刷新输入时，先限定本次已批准的任务 ID/刷新轮次，再检查来源和生成文件；其他阶段的待办不参加本次物化，但完整历史仍用于证明谱系。新项目沿用同一个规则。已有 Relax 输入若因本地压缩清理而缺失，优先从可验证的原归档恢复到原路径；保留 batch/job/task/checksum，不重新准备或重投。无原包、原包损坏或有执行/取消记录时返回具体任务和恢复说明，须补传或核对原记录，不能把未知状态重置成 pending。

| 现象 | 程序处理 | 人工需要做什么 |
| --- | --- | --- |
| JSON 语法/字段类型不正确 | 报告文件行列或配置字段，拒绝无效值；支持运行时 JSON 的 UTF-8 BOM | 修正指定文件，重新读取配置；不修改 Python |
| 边界、母结构、阶段参数不齐 | 配置或阶段入口校验阻止无效动作 | 补齐对应文件与字段，重新确认变更 |
| 某项回传文件被占用、损坏或标记不符 | 单项记录错误，其余可验证结果继续回收 | 解除占用或补传该项结果及完成标记，再回收原任务 |
| 执行中断、任务仍占用、提交状态不明 | 保留原选点、审批、回执和预算预留，禁止凭异常自动重投 | 在控制页“执行恢复与审批”核对外部作业、产物和成本，生成并审阅恢复方案 |
| 结果已经批准入账，但写入中断 | 保留事务状态，可从原恢复入口续写 | 核对事务版本后恢复；不要删除状态或重新导入整批 |
| 对话历史某条损坏或日志写入失败 | 跳过无效记忆行；可选节点日志失败不推翻业务结果 | 正式状态和回执优先；需要时检查目录权限和磁盘空间 |
| Windows 长路径、中文或特殊字符 | 只读 SQLite 路径统一编码，测试子进程使用常规路径拼写 | 保留原文件，按诊断定位；无需移动数据库绕过编码问题 |

“继续”不等于批准，“已准备输入”不等于已提交，“回传文件存在”不等于结果验证通过。失败时不要重新上传或提交整批；先检查原任务的回执和结果。详细人工操作仍见 [启动与调试](start.md)、[DFT](dft.md) 和 [训练](training.md)。

已核验但有终态失败的批次按成功覆盖显示，例如 DFT 12/13 或 MC 197/198。此时只给两条路径：继续使用成功子集并明确标注覆盖不足，或仅针对失败任务生成单项重试；原失败记录保留，不能重跑或重建整批。若失败结构是相图边界或关键候选，优先补全；否则可先继续分析。

## 修改模块和验证

### 已有环境在新流程中显示缺失

`run_project.py --check` 的 `python_environments` 分节显示每项实际值、来自确认配置还是 `agent_runtime.json`、以及缺项；不会调用模型或连接超算。旧版本可能只在提交脚本里写过 `conda activate ...`，这不等于新配置字段已经保存。核对原项目已使用的脚本后，可把相应环境名补入该项目 `agent_runtime.json` 的 `python_environments`，不改写冻结科学快照。已确认的非空环境值始终优先；本机环境不作为超算环境的默认值，也不会从其他项目自动复制。新项目继续在初始配置中明确保存两端环境。

DFT 在方案审批前、动作图派发前和实际输入准备前检查远端 MLIP 环境。缺项保留原选点并提示具体字段，不调用模型重新选择结构，不先生成空批次目录。已发生的失败仍按原执行恢复记录核对，补齐配置不等于自动批准或重放旧调用。

交互记录 Markdown 的 branch/DFT 方案部分单独列出本轮理由、方案取舍、已保存证据和逐区域/结构理由。缺项显示“未记录”，不补造历史科学判断；这些细节只进入报告，聊天与简版 TXT 清单保持简洁，也不额外调用模型。

流程入口和扩展位置见 [源码指南](../architecture/development.md)。在 py1 中运行：

```powershell
python tests/recovery_release_gate.py
python -m ruff check phase_agent
```

发布回归使用最小合成数据和假后端，覆盖配置入口、对话、审批、执行中断、结果回传、入账恢复和检查点。临时目录在运行后清理。真实项目大样本测试必须显式启用；真实模型、GPU/DFT 和超算环境需另行验收。正在运行的服务由用户按原方式重启后加载新源码。
