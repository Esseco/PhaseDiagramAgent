# Natural-language intent and context budget

Production chat uses one routine resolve_chat_intent call for messages not handled by deterministic read-only/navigation/approval entries. It receives an allowlisted current-state summary, training wait stages, registered candidate-review targets and at most four recent user/assistant messages. The serialized facts have a 3600-character cap; dialogue messages are capped at 450 characters. The request instruction and current user message are additional input, so this is not an exact tokenizer/cost limit.

The client disables deep reasoning for intent routing and caps its normal output at 512 tokens. Answers and clarifications are returned from that same call; the production handler does not make the legacy second read_only_conversation call. Compatible recover/analyze/next-step requests route to the existing workflow, not directly to a scientific tool. Explicit workflow feedback retains original text. Semantic configuration reads open the existing reviewed config revision. Clear activation/rejection requests must name a registered candidate (or uniquely resolve its reference), provide a review reason and pass all existing artifact/version/validation checks; generic continue/okay never grants activation. Low-confidence or ambiguous requests clarify rather than guess.

Studio may send only the latest message. The handler keeps a four-message in-memory dialogue tail per bound session, capped locally before transport. It is discarded at restart; current business facts and LangGraph wait checkpoints remain durable. This intentionally avoids persisting full chat histories or generating LLM summaries on every turn. Program state is authoritative; conversation text is context data, not independent authorization.

Deep Agents is an optional scientific proposal adapter in decision_layer/agent/deepagents_proposal.py, enabled only with proposal_harness=deepagents. The default current runtime is legacy. Neither routine conversation context nor project long-term memory is managed by Deep Agents. Existing prepare_llm_request compacts scientific request fields; project memory remains evidence-based and reviewed. Selecting Deep Agents is not required for bounded natural-language routing.

Legacy normalize_chat_intent callers retain opt-in second-call fallback for compatibility. Production explicitly selects enable_context=True and single_pass=True. No activation, HPC computation or service restart was performed by these changes.

Verification: py1 chat, configuration, registered-candidate, native graph and failure-boundary regression tests; mocked routing outputs verify one call and bounded context. Actual provider intent accuracy and token usage still require observing real conversations; no empirical recognition-rate or monetary saving is asserted.
