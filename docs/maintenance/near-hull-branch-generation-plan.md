# 近凸包驱动的 branch 生成

## 规则

- composition、competing_phase、tm_ordering 从当前模型正式相图 Ehull ≤ 0.005 eV/atom 的结构中选择父 branch。证据包括模型、相图版本、结构、哈希、Ehull 和父 branch 的 H；执行前重新核验。
- composition 在相同 P/H/T 下只选择完整合法组成网格中最近的低、高相邻 Na 含量，再与获批目标区域取交集。初态从父结构改变一个 Na 位点生成，保留其余原子及晶格；Na 位点无法可靠映射时报告失败。
- 父 branch 登记的 H 是超胞来源，弛豫后的晶格不要求精确反算成相同 H；竞争相和周期扩展按获批方案使用目标 H。
- Agent 对多策略方案给出合计为 1 的目标比例；不预设固定数量。程序根据新增候选受控抽样，并记录目标和登记后的实际分布；候选不足、去重和资源保护可能造成偏离。小批次尽量给低占比策略留出抽样机会，不声称比例精确。
- 策略必须通过配置和体系合法性校验。固定单一 TM 的 Ni 体系不使用 tm_ordering；首轮 coverage 契约不变。

## 边界

相图记录实际相与原 branch 不同的近凸包结构当前不自动作为父结构；预览中保留排除信息，避免以错误相/超胞身份生成。一个 branch 有多个符合条件且相同的近凸包结果时，目前选其中最低 Ehull 的一个作为该 branch 的父结构。需要额外覆盖这些情形时须明确建立实际相到可用框架的映射。

本实现改变方案校验和生成行为；旧冻结方案须按现有入口重新核验，不能自行更改其审批。真实项目的科学决策、生成、Relax/MC 与作业提交仍按既有审批流程进行；代码修改不重启真实服务。

## 核验

py1 下使用最小合成数据验证阈值、旧模型排除、结构哈希、父 branch H、Na 位点继承与相邻组分、策略比例及小批次、入口合法性、审批/生成回归。针对性回归 186 项通过；ruff check 与 format 检查 phase_agent 通过。Ni epoch1 的只读检查确认 29 个近凸包父 branch 文件及组成匹配，其中 18 个含 Na 结构的位点映射通过，11 个为 Na=0。单独的 Ewald 初始化/登记完整测试曾因耗时中断，未计入通过项。
