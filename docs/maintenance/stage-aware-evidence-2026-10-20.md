# 按阶段组织科学证据与分析（2026-10-20）

原先的大型科学调用缺少明确的问题范围，读取 history 可能同时展开重复执行快照。
本次复用原有轻量取证调用，先给出当前模型/配置、登记状态、按模型统计的任务状态、
模型刷新、新 branch、DFT 评估和收敛记录。阶段事实允许重叠，旧/未知模型身份明确标记，
由 Agent 结合当前用户原文解释阶段；程序不选择路线，也不删减 allowed_tools。

ScientificEvidenceRequest 在原主题请求上增加可选 analysis_plan（stage/question/reasoning）
和 fields（主题内的精确顶层字段名）。Agent 可选择 routine/scientific、跨阶段取证、
修改问题或升级思考。正常路径仍是取证、分析两次调用；不增加独立规划调用。
缺少或无效的分析方式采用原有保守科学推理策略，配置对话仍不启用科学思考。

原始 sources 和完整 evidence_revision 保留。仅 event_history、invocations、action_records、
agent_state_summary 默认索引，不自动传输；任何这些字段均可按名字完整读取。
历史科学 decisions、预算预留及未知的新科学字段仍按原主题默认可见。
独立 field_index 记录数量、序列化字节数及 on_demand；字节数不是 token 估算。
候选池、指标、人工约束不抽样；选择动作前按原主题补齐全部必要字段，
部分取证不能冒充完整候选池。缺失与空池不同，未知状态不能推断成无数据。
原始事实验证、审批、防重、每轮一个科学动作及取消/总时限规则继续有效。
过程记录包含本轮分析范围、实际新增字段及加载字节数，不保存模型原始思考。

## 限制

取证阶段对 analysis_plan 保持兼容：旧客户端未返回时使用原策略。Agent 仍可能选择
较多证据或较长推理；优化不能保证每轮减少相同比例。对明细有疑问应按字段补读，
而非把索引当科学结论。真实 API 的可靠性、token 和耗时节省尚未在线测量。
