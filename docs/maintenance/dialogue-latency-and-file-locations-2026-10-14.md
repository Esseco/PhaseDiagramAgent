# 交互延迟、实际答复及 JSON 位置提示修正

2026-10-14。

已确认根因：FeMn 的“重新生成branch”被历史重做关键词路径接管。本轮记录总耗时563.703秒，rerun节点532.516秒，无模型API调用。1188个关联任务中137个没有直接输入文件，每次回退都重新建立66批、约1189目录的磁盘索引。Studio又用旧待审批卡替换实际答复，过程页共用消息锁，运行时难以查看。

修正：普通自然语言重做/生成请求回到现有Agent决策和审批链；历史识别工具保留，但不再抢占普通消息。仅已有DFT重做记录的精确确认/拒绝兼容处理保留。文件索引在一次历史识别中懒加载最多一次，空索引也不会重复扫描；不使用跨轮缓存掩盖变化。Studio保留原答复，必要时追加待审方案，不覆盖处理结果。

过程页：现有计时钩子同步更新小型、按项目隔离的内存阶段记录；显示当前步骤及步骤/整轮已用时间，活动期间每3秒刷新，完成或异常后清理。读取不再等待消息锁。只展示可核对阶段，不展示模型内部推理，不保存每个步骤的完整科学状态，不批准或重放任务。聊天依然只返回最终助手答复；运行中阶段可从 /phase/process 查看。

JSON：branch和DFT审批/结果提示均显示“文件夹”“文件名”，供资源管理器定位并用VS Code或记事本打开，不再伪装为网页可打开的E盘链接。JSON结构和现有文件不变。

性能核验：同一FeMn真实状态快照，只读核对1188任务、1051已有输入，新索引构建1次，耗时1.034秒；原节点532.516秒。这里只比较旧慢点，不代表含模型调用的整轮响应时间。没有重新生成branch、运行DFT/MLIP/Slurm或改变项目状态。

生产源码针对性回归32 passed / 2 deselected：1200任务索引最多一次、全直接输入不扫描、普通请求不拦截、已有明确确认仍需新鲜方案、实际答复保留、忙时读取过程、嵌套步骤/异常清理和项目隔离、文件位置及branch/DFT详情兼容。两项旧Studio启动/共享运行时测试的精确展示字符串断言在修改前原源码也复现相同失败（额外项目名/简洁正文/预算），未改相关行为。Windows asyncio回环初始化在沙箱中阻塞，假服务测试在沙箱外运行；未操作真实服务。Ruff检查通过。

部署前逐一核对源码和测试基线哈希并备份，原件在工作区 build/dialogue_latency_fix/baseline；性能记录benchmark.json。用户手动重启FeMn服务后加载修正。未删除科学历史、结构、结果、模型、审批或预算。
