# 远端相识别：尚待完成的交接

Relax–MC 已通过 CPU phase controller 在每波终态回收后运行现有科学反馈和相识别。结果带结构摘要和跨路径规则绑定，回收时仍由本地规则及结构核验；单点结果仅在结构和规则一致时继承证据。旧证据按原路径检查或重新识别。

普通手动 Relax 和 DFT 弛豫目前没有上述波次 CPU 控制器，不能声称已实现批量远端识别。后续需要复用 submission_handoff 与 submission_dispatcher 的 afterany 收据机制，在同一批准范围下对完整任务清单创建 CPU 汇总作业；持久化规则和参考结构，校验各任务完成标记和最终结构，保存绑定原结果摘要的识别证据；通过现有最小传输清单回传，回收时核对结构及规则后才使用。作业缺失、失败或 CPU 中断必须可恢复，不能重放科研任务，旧包仍按原流程回收。

DFT 单点的输出几何可能与来源结构使用不同序列化形式；尚无可证明的同帧绑定时应保持未知或走现有验证，不得凭 structure_id 或近似几何假定一致。应增加合成跨作业依赖、失败恢复、CPU 回执、旧包及原子结构变动测试，禁止把识别结果当作新计算或改变已有审批。

## 模型刷新 CPU 波次

新准备的完整模型刷新波次，在既有交付包中登记一个依赖全部 GPU 子批次的 CPU 相识别作业。它先核验全部终态回执与最终结构，再将相识别另存为 `phase_identification.json`；原始 result.json 和完成标记不被改写。回传包保留该文件，本地回收核对任务、原结果和结构校验和，再按当前规则核验识别证据。已发生弛豫的结构重新识别；纯单点仅继承绑定相同结构与规则的既有证据，缺少可信来源时记为未知。

CPU 依赖作业无 GPU，采用现有 Relax–MC CPU 配置。未全部回传、结果不符或 CPU 环境失败时，不生成伪完成；保留已计算结果，不自动重投。已发出的旧包、分批发送的混合波次按原契约处理，可能需要本地识别。CPU 失败后的人工排查与重新交接尚需独立验证；不推断失败等于未执行。独立手动 Relax 与 DFT 弛豫仍未接入此 CPU 波次。

## CPU 分组

新提交的完整模型刷新和 Relax–MC 阶段，以任务清单每 200 项为一组：不超过 200 项使用一个 CPU 作业；超过 200 项使用 Slurm CPU 数组并行识别。CPU 任务等待本阶段全部 GPU 作业结束；每组核验完整阶段的终态回执和自己的结构，保存绑定冻结清单及任务结果的独立组回执。模型刷新由最后的 CPU 作业核验全部组后发布回传，Relax–MC 原协调作业在核验全部组后再更新凸包或推进下一阶段。缺失、损坏或不一致时保持阻塞，不自动重投。已冻结旧包和未启用分组的旧阶段沿原协议恢复；获批准的 Relax–MC 重试创建新的组身份，不复用旧组回执。

CPU 分组不改变科学识别规则：纯单点仅继承已核验的同结构相，弛豫结果重新识别；无法核验的相保持未知。真实 Slurm 环境、队列资源和失败后人工恢复仍需现场验证。
