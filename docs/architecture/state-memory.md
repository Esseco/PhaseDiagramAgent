# 状态、检查点与记忆的存储边界

轮次评估分别记录 DFT 评估、同帧证据核查、报表导出、反馈周期登记和状态保存耗时。DFT 单轮报表可在源证据版本、已登记目录和报表校验和匹配时复用。复用记录位于分析元数据目录，可随时重建；缺失旧记录、报表损坏或图文件缺失时走原发布流程。正式评估、跨轮汇总和状态保存仍由原流程完成。在 py1 环境运行 `python -m tests.benchmark_round_assessment` 可执行合成基准，添加 `--baseline` 可关闭单轮报表复用作对照。

图状态只保存可序列化的流程事实：当前节点和阶段、请求身份、暂停/恢复信号、`business_frame` 中尚未提交的业务事实，以及完成答复。客户端、管理器、锁和回调属于 Runtime context。`wait_for_project_input` 的 interrupt、`request_id`、待审方案身份、配置/模型版本和执行回执是恢复与防重放所需的最小事实；它们不能从 checkpoint 删除或改用答复缓存替代。

生命周期 checkpoint 通过 `checkpoint_frame` 只投影登记字段，并由 `CheckpointBlobSerde` 对大字段做版本化 CAS 引用和压缩。旧 LangGraph JSON、zlib 和 CAS 编码仍可读取；缺失或校验和错误会阻断恢复，不能清空 checkpoint 或重放科学动作。每个独立业务状态仍独立解码；同一 checkpoint 内明确共享的状态保留共享关系，恢复后再由 `restore_frame` 脱离为可变副本。

项目 `state.json` 和 ledger 仍是科学事实的权威来源。当前状态、任务、审批、预算、执行回执和已有历史保留在原格式；`current_state_snapshot` 是有版本的 Agent 视图，`state_snapshots` 只保存可重建的摘要索引。当前读取路径会在一次 turn 内转移已校验的初始状态所有权，避免同一文件被重复解析；文件与 `.control.json` 的设备、inode、大小、mtime 和 ctime 组成读取版本。指定的版本核对写入入口会拒绝跨进程替换后的旧写入；尚非所有写入路径都具备这一保护，盲写同样不能靠读取版本检测。正式写入仍须使用项目 control/ledger 机制。

状态写入还会生成 `workflow_state/state.view.json`。它是带源版本校验的可重建缓存，只保存任务状态行、审批/方向摘要、当前模型与刷新标记、状态计数和最近生成批次；`state.json` 与 ledger 仍是唯一事实源。视图缺失、损坏或版本过期时从完整状态重建，不能用于批准、恢复或科学决策。Codex/Agent 的只读任务列表和项目目录概览优先读取该视图，`pending()`、正式决策和恢复仍读取完整且经 control 校验的状态。

历史明细按需读取的边界先保持保守：任务、`action_records`、`generation_history`、`invocations`、审批、预算和回执同时参与恢复、防重放或正式决策，不能仅按字段名迁移到旁车文件。精简目录 `context_overview.json` 只作带源版本的快速入口，失效时可重建，不能授权或替代科学事实。长期记忆仍保留审核状态、证据引用和适用范围；短期观察只进入本轮上下文。本轮不接入 LangGraph Store，跨线程共享记忆若以后确有需求，应先定义 namespace、迁移和旧项目回读方案。

模型激活是状态复制的热点。已通过审批的激活路径拥有当前完整状态，只对被标记为旧模型结果的集合和模型注册表做 copy-on-write；训练候选生成、拒绝候选及旧恢复路径继续使用防御性深拷贝。这样不会删除历史，也不会把刷新审批变成自动执行，只避免无关任务和审计历史被递归复制数次。

检查点 pending write 对新批量编码器和旧的单值 `dumps_typed` 适配器都兼容；序列化仍在数据库游标锁外执行，旧 checkpoint 不需要重写。

性能基准使用受控合成项目，不代表真实科研项目。比较结果保存在 `docs/maintenance/state-memory-*.json`；真实项目不需要自动迁移，后续迁移必须经项目 Agent 正式入口和既有审批流程。

本次状态控制回归覆盖 Agent/Codex、审批、checkpoint、旧状态读取、版本冲突、并发写入和激活恢复，共 181 项通过；随后又通过 53 项核心状态/checkpoint 测试和 58 项 Studio/runtime 状态测试。2026-11-09 在 py1 环境运行完整 pytest，4634 项通过、38 项跳过、15 项子测试通过；测试运行期间补充的 DFT 重试修复另经相关 26 项测试验证。真实项目状态、服务、模型和 HPC 未做迁移或运行验证。

2026-11-09 跳过项复核发现，旧代码在对话读取、生命周期初始化和 checkpoint 恢复时自动精简旧历史，可能丢弃嵌套状态和决策上下文；上述自动精简已移除，旧历史在这些路径中按原内容保留。三个真实项目的状态文件曾只读复制到受控临时目录验证审批分支，未写入原项目。历史在本次修复以前若已被精简，不能从现有状态自动恢复；此前生成的新动作记录本身也使用摘要，不能据此声称拥有每次决策上下文的完整副本。旧基准生成于此修复之前，需重新测量后才能用于评价当前版本。

旧回收兼容路径、回收后失效路径及模型/配置改变导致的失效路径，现在将完整冻结方案保存在 `superseded_pending_plans`，并继续拒绝对失效方案的审批。旧回收兼容路径在已有控制锁内核对读取时的状态和 control 文件版本，冲突则拒绝写入；控制修复提交也在同一锁内发布 control 和 state。其他状态写入路径仍未全面启用文件版本核对：将上下文局部版本直接加到所有写入会误拦截不同 LangGraph 节点的正常恢复，跨节点和跨进程的一致性仍需单独设计和验证。已被早期版本截断的方案无法由新归档自动还原。
