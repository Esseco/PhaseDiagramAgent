# 收据对账与 LangGraph 恢复边界

执行收据表示某动作曾占用执行身份，不能作为计算完成证明，也不能清除后重放旧动作。
对账使用现有 `propose_reconciliation` / `apply_reconciliation`，保存证据与审核记录，保留原收据。
复用已登记工作时，任务状态、任务 ID、预算预留和输入文件不改变；后续仍走原结果回收。

## 区分输入缺失与结果等待

待执行/运行/已提交任务的 `result_path`、`calculation_result_path` 或 `results_directory`
尚不存在时，报告 `awaiting_result`，不再把正常等待当成输入损坏。
缺少输入、来源结构、续算 checkpoint 或已完成任务的结果，仍然阻止解除对账。
对账不推断未知超算作业的状态，不能把“未返回结果”标为完成。

## 使用现有图的恢复能力

主图仍为 initialize → observe → wait → analyze → react → finalize。
观察子图的前置执行检查只查收据，阻止未对账时推进训练或方向决策。
回收与科学反馈之后，wait 边界核验完整任务、文件及预算证据，避免同一轮重复扫描。
执行恢复子图使用条件边：无中断收据或仅需前置检查时，跳过完整文件检查节点。

业务事实未改变的观察节点不再次更新 `business_frame` 通道，保留原通道版本；事实改变时仍保存完整快照。
节点进度、错误和等待边界继续记录。没有删除现有 LangGraph 检查点，也没有改变主图节点身份。
原生 interrupt 等待新输入；Command(resume) 重新进入 initialize，读取最新台账。
同一请求重放复用已有检查点；新请求重新核对事实，不绕过科学动作审批和防重收据。

## 项目继续规则

已有任务等待回传时复用其目录与任务 ID，不重新生成或重投。
豁免等待的旧任务保留状态和来源；以后重新启用前需要核验输入及提交范围，豁免不代表完成。
模型更新仍需阶段边界。统一流程沿用上述对账与恢复规则。
只有结构目录、没有运行配置和工作流台账的目录，不能按已初始化项目继续。

默认相图子目录的设置比较使用实际 Runtime 的父工作区作为配置归属，
避免把运行命名空间误认为配置迁移目标。真正的参数编辑仍显示待确认；不改写确认配置。

清理仅移出无引用的源码备份到可恢复归档。科学输入、结构、结果、审批、模型和检查点保留。
