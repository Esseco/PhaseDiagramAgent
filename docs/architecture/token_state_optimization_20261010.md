# FeMn token 与状态体积优化（2026-10-10）

科研快照传输：203,968 → 147,285 bytes，减少 27.8%。这是字节变化，不是供应商计费 token 的实测变化。82 个候选、145 个 branch 的 ID、组成、能量、QBC、版本均保留并核对，覆盖表逐行等价。

state.json：76,535,994 bytes；同样内容紧凑编码为 43,886,788 bytes，减少 42.7%。文件大小不等于模型输入量。

## 实现

- 覆盖/候选清单使用无损 column_table_v1。common 是每行共有字段，columns 与 rows 对应不同值；混合 schema 保持对象列表，缺失与 null 不混同。
- legacy 和 Deep Agents 均支持；DFT 输出预算按真实行数计算。
- 存在待审批方案时，已有控制命令“继续/continue/继续原运行”展示原方案并绑定审批身份，不调用 LLM 重做科研决策。修改请求仍进入原模型流程；敏感操作仍要求审批页。
- state.json 原子写入使用紧凑 JSON；其他文件仍有缩进。数据和审批身份不变。
- 新调用按 mode 记录用量，保留最近 20 次调用及传输字符数；不反推历史调用分类。

## 生效与验证

使用 py1、假模型及假后端；没有真实供应商调用、模型激活或超算提交。已核对真实 FeMn 状态的传输等价性。已在确认全部会话空闲后重启 FeMn 服务并验证健康。持有项目锁时备份并无损重写了 state.json，实际体积已降到 43,886,788 bytes；完整数据与审批身份保持一致。102 项回归通过，ruff 检查与格式检查通过。
