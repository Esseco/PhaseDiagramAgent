# Codex 读取与记忆诊断

范围：当前磁盘源码；使用 py1、假模型与合成项目。没有读取或复制真实科研项目，没有计算、上传、提交、部署或服务重启。本记录区分源码和运行中服务；已有服务不会因磁盘代码修改自动获得新行为。

## 已有能力与根因

原有上下文投影、字段索引、单次字段复用、精简响应、角色子任务、澄清、审批与版本保护均保留，没有建立平行事实库或调度器。

原调用链：MCP选择项目 → CodexOffline构造完整普通运行时（读状态/台账、构造客户端）→ LocalAgentControl.codex_context（先台账文件校验、对象摘要，再查缓存）→ 字段索引/全量回退 → 单字段读取/解码 → 索引全内容校验 → 证据派生 → 团队另读同一状态 → 前后整文件身份校验 → 快照复制/哈希 → 角色投影 → 表格压缩 → 响应序列化。HTTP和聊天仍通过原Control/工作流处理事务，传输适配不另写科研状态。

| 步骤 | 原来的实际成本 | 本次处理 |
|---|---|---|
| 项目选择 | 默认构造完整运行时；只查目录也已支付初始化成本 | 已保存项目先复用SavedReadOnlyProject；目录、状态、待审、记忆浏览无需科学运行时；需要时升级一次 |
| phase_overview | 独立查询入口，命中只读小概览；不会自动供团队决策使用 | 保留独立浏览用途，补充真实详情入口与来源信息；不把它变成授权或事实源 |
| state.view | 失效会全量读取；包含current_state_snapshot、完整待审方案及刷新嵌套对象 | 去除嵌套快照，改定位信息；待审/方向/刷新只存元数据；有效字段索引可重建视图而不解析无关历史，未知计数为null |
| 字段索引 | 减少解析对象，不消除完整内容扫描；不兼容访问可回退 | 保留强校验，记录命中、字段字节、缓存命中和回退原因；单次团队/控制读取复用同一字段对象 |
| 团队重复请求 | 即使control缓存命中仍读字段、派生证据、重建快照、压缩角色 | 两个固定序列化缓存槽位：团队派生上下文与压缩后的角色视图；每槽96MiB，最多192MiB；来源/用途变化替换，5分钟后下次访问过期，超限不缓存 |
| 台账 | 缓存命中前仍扫描文件并编码整个可变manager.data | 增加真实计数/计时；本次没有取消这项一致性保护 |
| 直接context缓存 | 状态部分此前主要依赖mtime/size等展示签名 | 改为内容级来源绑定；命中也核对前后版本。团队复用其外层强身份，避免再重复扫描 |

新浏览链：MCP选择已保存项目 → 现有只读绑定 → 概览命中（小JSON与来源元数据）→ 指定详情入口。新决策链：强state/control身份 → 控制上下文核对配置/台账 → 相同来源与查询的团队派生缓存或一次字段读取/派生 → 再次强内容核对 → 快照 → 角色压缩缓存 → 序列化。缓存不取代审批，正式动作仍重新进入原工作流及冻结范围校验。

概览的元数据命中只适用于浏览；正式决策不用它授权。来源未变的团队缓存命中仍读取两遍state/control内容；这不是零I/O方案。冷请求仍核验索引的所有字段。缓存保存不可变JSON字节，返回值重新解析后独立持有，调用方修改不会污染后续请求。

## 记忆正确性

复现测试先失败：同一陈述/范围、v1/v2或不同证据产生同knowledge_id，审核返回approved但只存v1且version不增加。修复保留最初历史knowledge_id作为可解析旧引用；knowledge_family_id表示同一陈述族，revision_id绑定模型、适用范围、成熟度和证据版本；后续修订拥有独立knowledge_id和supersedes关系。人工批准后才替代旧版、保存新记录并增加memory version；身份碰撞或待审内容被改写直接拒绝，不伪报生效。审核回执增加实际knowledge_id/revision_id/applied/memory_version。

批准记录保存证据指纹与反向依赖。EvidenceResolver只索引本次引用的证据集合，同操作复用；不再对每条引用反复扫所有集合。检索会排除丢失、隔离、撤回或版本变化的证据，返回needs_revalidation原因；只读检索不写项目。下一次正常、已获授权的状态保存标记needs_revalidation并记录记忆版本/历史。旧validated记录没有证据版本绑定时要求重新核验；历史ID不迁移。旧无指纹的heuristic仅能校验当前引用存在/显式失效，不能复原过去证据内容。

validated的科学收敛及人工接受标准保留。流程经验可先使用既有project_observed/heuristic；本次未自行定义“流程已验证”的新标准。检索使用实际团队问题、角色子任务，以及原Agent的科学问题/失败类型；用途变化也使缓存失效。当前human_constraints和适用的已批准用户约束单独保留，不受建议检索预算裁剪。

同一经验来源的状态/成本变化形成修订链，旧记录保留，当前视图只有最新候选；相同输入不重复追加。decision_outcome不再复制完整action或团队上下文，改保留必要动作摘要、参数名与可靠来源引用。既有budget_experience已采用参数白名单，继续复用。

## 调用架构与边界

MCP/HTTP/CodexOffline仍调用LocalAgentControl及原事务入口；没有新增状态写入器。默认Codex运行时按operator=codex直接构造NoProjectModel，跳过项目客户端/凭据与模型切换器构造；重新构造的回调也保留该能力。注入的旧runtime_factory保留旧接口及事后NoProjectModel隔离，未保证第三方工厂内部没有副作用。

现有版本过期、缺证据、待回收、未授权和执行不确定的业务校验/状态保留；目录给出phase_context、phase_pending、phase_team_read及HTTP任务入口。复用phase_team_read的现有轻量历史/讨论摘要，不将聊天、团队意见当作科学事实。异常或超时不授予无副作用证明，不自动重试科学动作。

## 验证与剩余边界

大状态性能数据和来源SHA见read-performance-results.json；来源变化/回退和连续请求见read-scenarios-results.json。最初1.5GiB基准在依赖导入触及上限后退出，改用仅自有进程3GiB和240秒上限。测量过程发现早期角色缓存仍重复压缩，已把缓存移到实际压缩后；未把“响应变小”当作提速证据。机器计时有明显波动，使用最近配对样本并保留原始结果；不把初查13秒与后轮不同运行条件混比。

未实施：持久化迁移、task逐行随机读取/分页协议、可变台账对象的修订协议重构、取消强哈希、向量数据库或新的流程validated分类。缺少索引的旧项目仍完整读取且报告原因；不会在开发验证中为真实项目补索引。大台账文件/对象摘要仍可能主导等待，不能依据小台账夹具声称已解决。331MB真实项目、跨机器/跨进程缓存和真实客户端等待未验证。

MCP基准model_calls=0，client_wait_seconds=null，计时包含本地证据和序列化，不包含真实模型或界面处理。科学审批、冻结方案、历史恢复与防重放使用合成回归验证；没有测试真实HPC或真实服务。
