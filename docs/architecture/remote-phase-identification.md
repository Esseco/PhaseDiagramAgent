# Remote final-frame phase identification

Status: investigation and implementation plan; production changes are not yet complete.

The existing MLIP executor returns final geometry but does not call the local phase identification entry. The local recovery entry can already reuse an identification when final geometry digest and classification scope match. Its scope currently hashes reference file paths, sizes and modification times, so it is not portable across local Windows and Linux HPC. Empty-mobile-site classification may require reference structures. The portable inline-refresh executor is copied into tasks, whereas regular relaxation can use an installed phase_agent executor; an implementation must cover both without assuming the remote installed package contains new code.

Implement an explicit frozen, content-addressed classification contract in prepared task inputs, including phase boundary, mobile species, reference structure contents/hashes, algorithm version and source task/model identity. Ensure the remote runtime uses the exact same classification algorithm, and perform it after the final geometry exists for relaxation, inline-followup and MC. Transfer the evidence within the existing checksum-bound result; no new independent workflow or phase policy. Reuse a remote classification locally only after checking the final-frame digest, rule/reference and algorithm binding against current effective configuration. Missing, unknown, stale or mismatched evidence must take the existing local fallback; preserve outside-boundary and unidentified handling. Do not mutate historical frozen task inputs or require a new remote package version implicitly.

Synthetic validation must exercise O1/O3/P3, Na-free endpoints, references, valid/mismatched rules and geometry, unknown results, outside-boundary, regular Relax, MC and inline-refresh paths, result export/recovery, old frozen tasks, reference packaging and remote module availability. Measure added payload and avoid multiplying per-task copies of large code or reference files. Explicitly preserve existing cache compatibility; rule changes must not make old results silently current.
